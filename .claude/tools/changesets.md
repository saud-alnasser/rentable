# changesets

How a user-visible change gets into the changelog and into a release.
`.claude/policies/version-control.md` says *when* one is required; this says how to write it.

The package is **private**, so nothing is published to npm. `privatePackages` in
`.changeset/config.json` sets `version: true` and `tag: true` — changesets bumps the version
and the release workflow tags it, and the tag is what triggers the signed Tauri artifact
build. The changelog is generated by `@changesets/changelog-github`, which turns each entry
into a line crediting the pull request.

Docs: <https://github.com/changesets/changesets/blob/main/docs/intro-to-using-changesets.md>.
Fetch before changing `.changeset/config.json` or reaching for a command below not listed.

## Add a changeset

**Write the file directly.** Do not run `pnpm exec changeset` in a non-interactive
session — it is a prompt-driven wizard (which package, which bump, then a summary) and it
hangs with no terminal attached.

A changeset is a markdown file in `.changeset/` with any unused name. The generated names
are three random words; anything unique works, and the file is deleted on release:

```markdown
---
'rentable': patch
---

summary in the imperative, lowercase, one line
```

`'rentable'` is the only package. The bump is `patch`, `minor`, or `major`, and it drives the
version directly — there is no separate release-notes step where it can be corrected later.

The summary lands in `CHANGELOG.md` verbatim, so write it for someone reading release notes,
not for a reviewer reading the diff.

## When one is not needed

Dependency bumps and internal refactors that no user can observe do not get a changeset.
A missing changeset on a user-visible change means it ships without appearing in the
changelog — the failure is silent, since nothing in CI checks for one.

## Never run the release path locally

```bash
node .github/changeset-version.cjs   # do not run
node .github/changeset-tag.cjs       # do not run
```

Both belong to `.github/workflows/release.yml` and both are destructive outside it.
`changeset-version.cjs` runs `changeset version`, then rewrites `tauri/Cargo.toml`'s version
to match `package.json` and refreshes both lockfiles. `changeset-tag.cjs` **creates a git tag
and pushes it** — publishing, and the human's call under the standing rule in
`.claude/rules/engineering.md`.

On `main`, `changesets/action` opens a `chore: version package` pull request that consumes
the accumulated changeset files. Merging that pull request is what releases.
