# eslint

The linter, and the other half of the CI gate. **CI runs `pnpm exec eslint .` directly**,
not `pnpm lint` — `pnpm check` has already run the prettier half, and `pnpm lint` would run
it a second time.

ESLint 9 with **flat config** in `eslint.config.js`: the recommended sets for JS,
typescript-eslint, and Svelte, with `eslint-config-prettier` last so formatting rules never
fight prettier.

Docs: <https://eslint.org/docs/latest/use/configure/configuration-files>. Fetch before
adding a config object or a plugin — flat config composes as an ordered array, and where an
entry sits changes what it overrides.

## Lint

```bash
pnpm exec eslint .           # what CI runs
pnpm exec eslint . --fix     # apply the autofixable subset
pnpm lint                    # prettier --check + eslint, for local use
```

## Lint one path

```bash
pnpm exec eslint src/lib/contract/router.ts
```

## `.eslintignore` is dead — ignores come from `.gitignore`

There is **no `.eslintignore`**, and adding one back would do nothing: ESLint 9 does not read
it, warning `The ".eslintignore" file is no longer supported` and carrying on. One was here
until it was removed for exactly that reason — it had gone silently dead, and `tauri/target`
was being walked as a result.

The ignore set is two things and nothing else:

```js
includeIgnoreFile(gitignorePath)              // the root .gitignore
{ ignores: ['tauri/**', 'src/lib/i18n/i18n-*.ts'] }
```

The explicit entry covers what `.gitignore` does not. `tauri/target` holds over a hundred
`.js` files of Rust build output and is not gitignored at the root; the `i18n-*.ts` modules
are generated by typesafe-i18n. Both are machine-written, so anything reported in them is
unfixable at the source.

**The glob is narrower than it looks, deliberately.** `i18n-*.ts` catches the generated
modules but not `src/lib/i18n/ar/index.ts`, `en/index.ts`, or `formatters.ts`, which are
hand-authored and stay linted.

To exclude something, add it to `.gitignore` if it genuinely should not be tracked, and
otherwise extend the `ignores` entry. Never `.eslintignore`.

## Markdown is not linted

No markdown plugin is configured, so ESLint reaches no `.md` file — including everything
under `.claude/`. The `.claude/` protection there is prettier's, not this tool's.

## Rust is not covered

Neither `pnpm check` nor `pnpm lint` touches the Rust side. See `cargo.md`.
